# Cross-platform build and CI checks: design

## Intent

Let the ROM builds and the PinMAME boot test run on macOS and Linux as well as Windows, so the user can
build from a Mac and CI can run on any runner. Then catch, on every push and
pull request, the mistakes that would make a ROM unsafe to burn or would break
the repository's preservation rules: source that no longer assembles, a broken
startup checksum, a changed canonical ROM, an altered immutable ROM, or
documentation that points at paths that no longer exist.

Work happens on branch `cross-platform-build`.

## Goals

### Part 1: cross-platform build

1. The three `src/*/asm/build.ps1` scripts run unchanged in behavior under
   PowerShell 7 (`pwsh`) on macOS, Linux and Windows, and still under Windows
   PowerShell 5.1.
2. Each script selects the DASM 2.20.14.1 binary for the host OS:
   `dasm-2.20.14.1-win-x64/dasm.exe`, `dasm-2.20.14.1-osx-x64/dasm`
   (runs under Rosetta on Apple silicon) or `dasm-2.20.14.1-linux-x64/dasm`.
3. A tracked `tools/Get-Dasm.ps1` downloads the pinned DASM 2.20.14.1 release
   for the host OS, verifies its SHA-256, and unpacks it to that path. Used by
   people and by CI.
4. The build readmes show the `pwsh` invocation alongside the existing
   Windows one.

### Part 2: cross-platform boot test

5. Each tree's `asm/test-pinmame.ps1` runs that tree's `build.ps1`, then boots
   the exact `eballchp.zip` the build produced in libpinmame, headless and
   unthrottled, for a fixed number of frames. It passes only if the displays
   update and the stack does not hold the return address into the `E3E0`
   checksum-failure loop, and U4 RAM is written. It requires PowerShell 7 on
   every OS (it uses .NET's `NativeLibrary` to load libpinmame by path);
   Windows PowerShell 5.1 is supported for builds only.
6. A C# class compiled in-process with `Add-Type` binds libpinmame and handles
   its callbacks on the emulation thread. No Python. The library resolver,
   callbacks and log formatting stay entirely in C#, because the emulation
   thread has no PowerShell runspace and an exception escaping a native
   callback kills the process. Events after the frame cutoff are not
   recorded, so results do not depend on host timing.
7. A tracked `tools/Get-LibPinmame.ps1` downloads the pinned libpinmame
   release (v3.7.0-477-6589fc5) for the host OS and verifies its SHA-256.

### Part 3: CI

8. Build all three trees and fail on any error the scripts raise.
9. Build `src/originals` with `-RequireByteIdentical`. This is also the
   canonical-versus-variation guard.
10. Fail if any file under `src/*/roms/` differs from its recorded SHA-1.
11. Fail if a Markdown link, or a backticked path beginning with `src/`,
   `docs/` or `tools/`, names a file that does not exist.

## Non-goals

- Rewriting the build in another language or merging the three scripts.
- Rule, switch, lamp, solenoid and service-mode tests; they belong to a later
  libpinmame test-suite project.
- Headless Ghidra replay in CI.

## Anti-goals

- Any change to a built ROM. Every tree's ROM SHA-1 and `verification.txt`
  hash lines must match between the old scripts on Windows and the new
  scripts on every OS.
- Publishing runnable ROM images. The repository is public, so CI uploads
  only `verification.txt`, listings, symbol files and hashes, never
  `eballchp.zip` or the Weebly `.bin`.

## Constraints

- Builds write the package to the gitignored `VisualPinballX/VPinMAME/roms/`.
- `.gitignore` ignores `/tools/*` except listed files; the new `tools/*.ps1` files must be
  added to the exceptions.
- Windows PowerShell 5.1 has no `$IsWindows`; an undefined value means Windows.

## Approaches

- **Keep PowerShell, make it portable (chosen by the user).** Smallest change
  to working scripts; needs `pwsh` on macOS and Linux.
- Boot-test host language: C# inside PowerShell (chosen by the user) over
  Python ctypes (proven in a trial, but a second language) or a C program
  (needs a compiler everywhere).
- Shared Python build tool. Removes the three copies and matches the future
  Python test harness, but rewrites working scripts.

## Design

- Replace backslash literals in paths with forward slashes, which every
  PowerShell accepts on every OS.
- Add a host-OS switch for the DASM path in each `build.ps1`.
- Boot test: `src/*/asm/test-pinmame.ps1` keep their names and build step;
  the PinMAME run moves to a shared `tools/LibPinmameBoot.ps1` holding the
  C# class.
- `.github/workflows/ci.yml`:
  - `rom-hashes` (ubuntu): compare `src/*/roms/*` to a tracked SHA-1 manifest.
  - `doc-paths` (ubuntu): run a tracked checker over `*.md`.
  - `build` matrix (ubuntu, windows, macos): `Get-Dasm.ps1`, then the three
    builds, then `Get-LibPinmame.ps1` and the three boot tests; compare ROM
    hashes across the matrix; upload the non-runnable
    outputs.
- One-time equivalence proof: a Windows runner builds `main` with the old
  scripts; its three ROM SHA-1s must equal the branch's builds on macOS here
  and on every CI runner.

## Left to the builder

Manifest and checker file locations and format; exemption list for
local-only paths in the doc checker.
